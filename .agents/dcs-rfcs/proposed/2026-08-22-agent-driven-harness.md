# DCS-RFC: The agent-driven harness — dcs-rfcs, layered instructions, skills, and documentation gates

Status: proposed

English | [中文](2026-08-22-agent-driven-harness.zh.md)

## Problem

This repository is developed primarily by AI coding agents — four tool harnesses (`.zcode/`, `.claude/`, `.codex/`, `.opencode/`) already delegate every format and lint decision to prek — yet the conventions that carry that working mode live as prose with nothing mechanical behind them. Decision rationale has no durable home: the why of hard-won choices (dropping the broker for a lock-free ring + slab, making prek the single gate source, the tiered test architecture) survives only in PRINCIPLES narratives and git history, where code and docs cannot link to it, so every revisiting re-argues from zero. The root `AGENTS.md` carries every subtree's orders — Rust build and style rules, the chat demo's acceptance procedure, release steps — at 1,242 words that every session loads in full regardless of task, with no budget to stop accretion. The README bilingual pair has silently drifted (1,128 English words against 736 Chinese) because nothing checks pairs. Skills mirrors under `.agents/skills/` and `.claude/skills/` are kept equal by hand, and the AGENTS.md ↔ CLAUDE.md gate only reports drift — the side an agent actually edited still has to be reconciled manually. The deepseek-harness reference project states the founding observation this record acts on: agents follow enforced gates far more reliably than prose conventions, and "a lot of work" is not a cost argument when agents do the labor.

## Proposal

**Documentation tiers, one fact one home.** The documentation standard lives in [`docs/AGENTS.md`](../../../docs/AGENTS.md): a tier map assigning each class of fact exactly one home, everywhere else links. [`README.md`](../../../README.md) + twin — user-facing product docs; [`PRINCIPLES.md`](../../../PRINCIPLES.md) + twin — behavioral principles, the live home (this project's principles are freshly written and referenced by the `iterating` skill; unlike markpost, PRINCIPLES is not frozen into the root's Conventions section); `docs/` — operation guides ([`docs/development.md`](../../../docs/development.md), [`docs/releasing.md`](../../../docs/releasing.md), [`docs/benchmarking.md`](../../../docs/benchmarking.md)) extracted from today's root AGENTS.md; [`.agents/dcs-rfcs/`](../README.md) — decision records; [`CHANGELOG.md`](../../../CHANGELOG.md) — ledger, narrating history by design and exempt from prose gates; agent-instruction files (`AGENTS.md`, `CLAUDE.md`, `SKILL.md`) — standing orders, English only; `examples/chat/` — a standalone uv project, exempt through the manifest. No `specs/` tier: design facts stay in the README overview and the code until a trigger signal arrives.

**Bilingual corpus, equal authority.** Every in-scope documentation file ships as a pair, `foo.md` beside `foo.zh.md`, same directory, both sides equal authority: either may be written or edited first, the edited side is the source for that change, and the twin follows in the same change as a minimal patch — never a wholesale re-translation; on substantive disagreement the wrong side is fixed, neither wins by default. Each side carries a header switcher linking its twin; relative links into the corpus follow the reader's locale; heading sequences and fenced code blocks stay byte-identical; machine tokens and section headings stay in English; the `.md` prose carries no CJK; Chinese uses half-width spaces around Latin and full-width punctuation. `README.zh-CN.md` is renamed `README.zh.md` — one spelling for one idea — and the drifted pair is re-synchronized; `PRINCIPLES.zh.md` is written. Exemptions live in an exclusions-only manifest, [`scripts/doc_languages.manifest.json`](../../../scripts/doc_languages.manifest.json): agent instructions, the CHANGELOG ledger, `examples/chat/`, tool-local state.

**dcs-rfcs — this project's RFCs.** Durable proposals and decision records living at `.agents/dcs-rfcs/{proposed,implemented,rejected}/yyyy-mm-dd-slug.md` (date = when the topic was first proposed, per git history), every record a bilingual pair. The tree carries two documents with orthogonal jobs: [`README.md`](../README.md) + twin is the normative contract — layout, lifecycle, format skeletons; [`AGENTS.md`](../AGENTS.md) holds the standing orders — duplicate check before writing, supersede-never-rewrite, keep the pair in sync. The header is exactly `# DCS-RFC: <title>` plus a `Status:` line that agrees with the folder; the body opens `## Problem`; `implemented/` continues `## Decision` → `## Alternatives considered` → `## Consequences` (present tense, proposal-era headings rejected); `proposed/` continues `## Proposal` → `## Alternatives considered` → `## Acceptance criteria` → `## Risks`; `rejected/` freezes the proposal with the verdict on the `Status:` line. `## Alternatives considered` is mandatory in every record — a decision recorded without what it beat invites re-litigation. Every non-trivial change adds or updates at least one record in the same change-set; purely mechanical or local edits are exempt. The opening corpus is this record plus three backfills grounded in the PRINCIPLES narratives and git history: the lock-free ring + slab over a broker, prek as the single source of every quality gate, and the tiered test architecture.

**Layered agent instructions with word budgets.** The root `AGENTS.md` slims to standing orders under an 800-word ceiling — identity, layout map, the command index, git workflow, boundaries, and an "Editing these instructions" section stating the mirror and budget contracts — while Rust orders move to [`crates/_channels_shm_native/AGENTS.md`](../../../crates/_channels_shm_native/AGENTS.md) (≤ 400), the demo's orders to [`examples/chat/AGENTS.md`](../../../examples/chat/AGENTS.md) (≤ 300), the documentation standard to [`docs/AGENTS.md`](../../../docs/AGENTS.md) (≤ 600), and procedures to their `docs/` guides. A subtree file supplements the root and never repeats it; `tests/` and `bench/` get no file (no toolchain of their own). [`scripts/doc_budgets.manifest.json`](../../../scripts/doc_budgets.manifest.json) + `verify_doc_budgets.py` enforce the ceilings — budgets are `wc -w` whole-file, a budgeted file gone missing fails the gate; on red, relocate, then condense, and raise the ceiling last with a justified manifest diff.

**Direction-free mirrors.** [`scripts/agentlib.py`](../../../scripts/agentlib.py) detects per-pair direction against git HEAD — never mtime, which clone and checkout reset: exactly one side differing from HEAD means that side is copied over the other; equal contents pass; both sides differing and disagreeing is a conflict the tooling refuses to guess through; a path absent from HEAD counts as changed on its side, which bootstraps new pairs. `check_agent_instructions.py` (gate) and `sync_agent_instructions.py` (fixer) share the module; the pair covers the root and subtree `AGENTS.md` ↔ `CLAUDE.md` copies and the skills trees, where `.agents/skills/` and `.claude/skills/` are equal copy mirrors with no primary. Symlinks are rejected: a Windows checkout materializes them as regular files holding the target path. The prek hook auto-fixes and stages the stale twin on an unambiguous single-sided change; a true conflict fails naming the sides, the fix command, and the reconciliation steps.

**Skills.** `.agents/skills/` is the tool-neutral home (loaded natively by ZCode and Codex-side tooling); `.claude/skills/` is its mirror. Two skills join `iterating` and `commit`: `writing-rfcs` (the record workflow — duplicate check, lifecycle, skeletons, validation) and `doc-standards` (placement, writing discipline, gate response). `iterating` gains the landing rule that decision-bearing outputs land as dcs-rfcs; `commit` carries the record-pair bundling and the `README.zh.md` naming.

**The gate suite and its wiring.** All gates are stdlib-only Python in `scripts/`, per this repo's scripts rule, sharing helpers in [`doclib.py`](../../../scripts/doclib.py) and aggregated by [`doc_sync.py`](../../../scripts/doc_sync.py), which runs them in sequence, keeps each independently runnable, and restricts scope to given file arguments: `verify_md_links.py` (relative links and `#fragment` anchors resolve — over the whole gated corpus, agent instructions included), `verify_md_wrap.py` (one physical line per paragraph), `verify_md_current.py` (current-state prose in README and `docs/` only; PRINCIPLES and records narrate rationale by design), `verify_dcs_rfc_format.py` (both languages' skeletons, machine tokens, header/folder agreement), `verify_doc_pairs.py` (pair completeness, switchers, link locale, structural parity, CJK purity), `verify_doc_budgets.py`. Wiring follows the existing prek doctrine: a `doc-check` hook joins the `lint` group and runs `doc_sync` on staged Markdown (prek stashes unstaged changes during hook runs, so a wider scan would see a stale tree); `agents-md-sync` becomes the self-healing `agent-instructions-sync` in the `format` group plus a `skills-sync` sibling. CI is untouched — the lint job already runs `prek run --all-files`, which executes every hook over the full corpus; the four AI tool hook trees are untouched for the same reason: they delegate to the prek groups, so new gates flow through automatically.

**Migration.** The batches land as one change-set in tiered commits, CI validating the end state: first the in-flight work already in the tree (PRINCIPLES.md, the `iterating` skill, the AGENTS/CLAUDE edits) commits as-is for a clean baseline; then the gate scripts and manifests land with the corpus normalized — paragraphs reflowed to one physical line, `README.zh-CN.md` renamed and its pair re-synchronized, `PRINCIPLES.zh.md` written; then the dcs-rfcs tree, its contract pair, the format gate, the `writing-rfcs` skill, and the backfills; then the AGENTS.md split with budgets, the mirror upgrade, and the `docs/` extraction; finally the full `prek run --all-files` runs green and this record moves `proposed/` → `implemented/` with its skeleton rewritten.

**Growth on signals, not speculatively.** Not ported, each with the trigger that would revive it: `.i18n.yaml` blob-hash sidecars and merge drivers (one-sided pair edits repeatedly slipping past review); an archived frozen tree with a sealed manifest (records accumulate past findability); `{class}/` subfolders inside lifecycles (class counts grow past browsing); a gate-scheduler DAG (gate count or runtime outgrows sequential execution); a `specs/` tier with an index gate (design facts outgrow the README overview); postmortems, PR/issue templates and policy automation (external contributors arrive); `grill-me`, `shipping`, and `release` skills (the workflows recur enough to codify). The reference project's full machinery is the recorded ceiling of where this road leads, not the starting point.

## Alternatives considered

**Port the deepseek-harness machinery wholesale.** It lost: this corpus is an order of magnitude smaller than markpost's, itself an order smaller than the reference; blob-hash i18n triplets, a frozen archive, a dependency-graph gate scheduler, postmortems, and issue-policy automation would each be the most complex script in this tree serving no need here. markpost's trigger-signal verdict is inherited deliberately — pieces arrive when a signal appears, never wholesale.

**Light wiring without layering — keep the single root AGENTS.md.** It lost: 1,242 words already tax every session with every subtree's detail, and without a mechanical budget the accretion continues; the load paths support progressive disclosure, so layering localizes the context tax where tools support it. Raised at review and declined in favor of the full split.

**Freeze PRINCIPLES.md into the root's Conventions section — markpost's model.** It lost: markpost froze a predecessor whose rules were migrating; here PRINCIPLES.md is freshly written, is the live home the `iterating` skill operates from, and no drift problem motivates a migration. Keeping it live and pairing it bilingual is the smaller, grounded change.

**Symlink mirrors — the reference project's mechanism.** It lost: git stores a symlink as a mode-120000 blob, and a Windows checkout without `core.symlinks` plus privilege materializes `CLAUDE.md` as a regular file containing nine bytes; nothing constrains contributors to Unix-like checkouts. Copy mirrors with HEAD-based direction detection work everywhere.

**A separate CI docs workflow — markpost needed one.** It lost: markpost's lint CI path-ignores `*.md`, so docs needed their own workflow; this project's CI runs `prek run --all-files` over everything, and a second workflow would duplicate that job for no path-ignore reason.

**A `specs/` tier now.** It lost: the design facts fit the README overview and the code today; a tier plus index gate is surface to maintain and pairs to translate before any signal demands it.

**Keep the `README.zh-CN.md` naming.** It lost: `.zh.md` is the convention the new corpus is born with; two spellings for one idea is its own drift, and the pair gate would carry two regexes forever. Renaming is one `git mv`.

**Split this introduction into five records, one per subsystem.** It lost: markpost's granular records reflect an adoption that unfolded over weeks; this introduction is one decision-event, reviewed and landed as a whole, and the subsystems share one migration. Granular records start with the next trigger.

## Acceptance criteria

1. `.agents/dcs-rfcs/` exists with its `README.md` + `README.zh.md` contract, its `AGENTS.md` standing orders, and `proposed/`, `implemented/`, `rejected/` folders; `verify_dcs_rfc_format.py` passes over every record pair, including this one in both languages.
2. The corpus is normalized and paired: `README.zh.md` (renamed, content parity with the English side), `PRINCIPLES.zh.md`, the `docs/` guides born paired; `verify_doc_pairs.py`, `verify_md_links.py`, and `verify_md_wrap.py` pass over the full corpus.
3. Layering is in force: root `AGENTS.md` ≤ 800 words, `crates/_channels_shm_native/AGENTS.md` ≤ 400, `examples/chat/AGENTS.md` ≤ 300, `docs/AGENTS.md` ≤ 600; `verify_doc_budgets.py` green, and removing a budgeted file fails it.
4. Mirrors behave direction-free, verified by drill in a scratch state: a single-sided edit of any AGENTS ↔ CLAUDE pair or the skills trees is auto-fixed and staged; identical edits on both sides pass; disagreeing edits fail naming the sides and the reconciliation steps; a new pair bootstraps from one side.
5. The gates are wired: `doc-check` runs `doc_sync` on staged Markdown through the `lint` group; `agent-instructions-sync` and `skills-sync` self-heal through the `format` group; `prek run --all-files` is green end-to-end; `.github/workflows/` is byte-unchanged.
6. The opening corpus is complete: this record plus three implemented backfills (ring + slab over a broker; prek as the single gate source; the tiered test architecture), each grounded in the PRINCIPLES narratives and git history it cites; on landing, this record moves to `implemented/` with `## Proposal` rewritten as present-tense `## Decision` and `## Acceptance criteria`/`## Risks` folded into `## Consequences`.
7. Product code and behavior are untouched: `uv run pytest -m "not slow and not e2e"` green, `cargo test` green inside the crate; the new scripts pass ruff under this repo's configuration.
8. Skills are in place and equal: `writing-rfcs` and `doc-standards` exist under `.agents/skills/` with `.claude/skills/` identical; `iterating` and `commit` updated as specified.

## Risks

Structural parity proves shape, not substance — a sloppy twin passes green, so review carries semantics, the cost markpost records for the same design. The bilingual duty taxes every future documentation change; proportionate at this corpus size, and the signal-gated upgrades (freshness records, PR-level co-change gates) stay deferred with named triggers. Word ceilings invite raise-churn; headroom plus the documented justify-in-the-manifest-diff path absorbs it. The staged-only pre-commit scope means full-corpus truth lives in CI and the AI Stop hook, not in every commit. Direction detection reads HEAD, so merge and rebase states that leave a pair disagreeing surface as guided conflicts, never silent copies. Ported scripts can carry porting bugs; the mirror drill and gate drills in the acceptance criteria exist to catch exactly that. The normalization batch touches every documentation file at once — reflow is mechanical, but any semantic edit rides separately and is reviewed as content.
