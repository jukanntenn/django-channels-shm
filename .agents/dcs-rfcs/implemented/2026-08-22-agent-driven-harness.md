# DCS-RFC: The agent-driven harness — dcs-rfcs, layered instructions, skills, and documentation gates

Status: implemented

English | [中文](2026-08-22-agent-driven-harness.zh.md)

## Problem

This repository is developed primarily by AI coding agents — four tool harnesses (`.zcode/`, `.claude/`, `.codex/`, `.opencode/`) already delegate every format and lint decision to prek — yet the conventions that carry that working mode lived as prose with nothing mechanical behind them. Decision rationale had no durable home: the why of hard-won choices (dropping the broker for a lock-free ring + slab, making prek the single gate source, the tiered test architecture) survived only in PRINCIPLES narratives and git history, where code and docs could not link to it, so every revisiting re-argued from zero. The root `AGENTS.md` carried every subtree's orders — Rust build and style rules, the chat demo's acceptance procedure, release steps — at 1,242 words that every session loaded in full regardless of task, with no budget to stop accretion. The README bilingual pair had silently drifted (1,128 English words against 736 Chinese, the zh side describing a retired `run_workers` flow) because nothing checked pairs. Skills mirrors under `.agents/skills/` and `.claude/skills/` were kept equal by hand, and the AGENTS.md ↔ CLAUDE.md gate only reported drift — the side an agent actually edited still had to be reconciled manually. The deepseek-harness reference project states the founding observation this record acts on: agents follow enforced gates far more reliably than prose conventions, and "a lot of work" is not a cost argument when agents do the labor.

## Decision

**Documentation tiers, one fact one home.** The documentation standard lives in [`docs/AGENTS.md`](../../../docs/AGENTS.md): a tier map assigning each class of fact exactly one home, everywhere else links. [`README.md`](../../../README.md) + twin — user-facing product docs; [`PRINCIPLES.md`](../../../PRINCIPLES.md) + twin — behavioral principles, the live home (this project's principles are freshly written and referenced by the `iterating` skill; unlike markpost, PRINCIPLES is not frozen into the root's Conventions section); `docs/` — operation guides ([`docs/development.md`](../../../docs/development.md), [`docs/releasing.md`](../../../docs/releasing.md), [`docs/benchmarking.md`](../../../docs/benchmarking.md)) extracted from the former root AGENTS.md; [`.agents/dcs-rfcs/`](../README.md) — decision records; [`CHANGELOG.md`](../../../CHANGELOG.md) — ledger, narrating history by design and exempt from prose gates; agent-instruction files (`AGENTS.md`, `CLAUDE.md`, `SKILL.md`) — standing orders, English only; `examples/chat/` — a standalone uv project, exempt through the manifest. No `specs/` tier: design facts stay in the README overview and the code until a trigger signal arrives.

**Bilingual corpus, equal authority.** Every in-scope documentation file ships as a pair, `foo.md` beside `foo.zh.md`, same directory, both sides equal authority: either may be written or edited first, the edited side is the source for that change, and the twin follows in the same change as a minimal patch — never a wholesale re-translation; on substantive disagreement the wrong side is fixed, neither wins by default. Each side carries a header switcher linking its twin; relative links into the corpus follow the reader's locale; heading sequences and fenced code blocks stay byte-identical (comments included — examples are not translated); machine tokens and section headings stay in English; the `.md` prose carries no CJK; Chinese uses half-width spaces around Latin and full-width punctuation. `README.zh-CN.md` was renamed `README.zh.md` — one spelling for one idea — and the drifted pair re-synchronized (the retired demo flow replaced with the shipped uvicorn one); `PRINCIPLES.zh.md` was written. Exemptions live in an exclusions-only manifest, [`scripts/doc_languages.manifest.json`](../../../scripts/doc_languages.manifest.json): agent instructions, the CHANGELOG ledger, `examples/chat/`, tool-local state.

**dcs-rfcs — this project's RFCs.** Durable proposals and decision records living at `.agents/dcs-rfcs/{proposed,implemented,rejected}/yyyy-mm-dd-slug.md` (date = when the topic was first proposed, per git history), every record a bilingual pair. The tree carries two documents with orthogonal jobs: [`README.md`](../README.md) + twin is the normative contract — layout, lifecycle, format skeletons; [`AGENTS.md`](../AGENTS.md) holds the standing orders — duplicate check before writing, supersede-never-rewrite, keep the pair in sync. The header is exactly `# DCS-RFC: <title>` plus a `Status:` line that agrees with the folder; the body opens `## Problem`; `implemented/` continues `## Decision` → `## Alternatives considered` → `## Consequences` (present tense, proposal-era headings rejected); `proposed/` continues `## Proposal` → `## Alternatives considered` → `## Acceptance criteria` → `## Risks`; `rejected/` freezes the proposal with the verdict on the `Status:` line. `## Alternatives considered` is mandatory in every record — a decision recorded without what it beat invites re-litigation. Every non-trivial change adds or updates at least one record in the same change-set; purely mechanical or local edits are exempt. The opening corpus is this record plus three backfills grounded in the PRINCIPLES narratives and git history: the lock-free ring + slab over a broker, prek as the single source of every quality gate, and the tiered test architecture.

**Layered agent instructions with word budgets.** The root `AGENTS.md` slims to standing orders under an 800-word ceiling (it lands at exactly 800) — identity, layout map, the command index, git workflow, boundaries, and an "Editing these instructions" section stating the mirror and budget contracts — while Rust orders move to [`crates/_channels_shm_native/AGENTS.md`](../../../crates/_channels_shm_native/AGENTS.md) (≤ 400, lands at 227), the demo's orders to [`examples/chat/AGENTS.md`](../../../examples/chat/AGENTS.md) (≤ 300, lands at 154), the documentation standard to [`docs/AGENTS.md`](../../../docs/AGENTS.md) (≤ 600, lands at 531), and procedures to their `docs/` guides. A subtree file supplements the root and never repeats it; `tests/` and `bench/` get no file (no toolchain of their own). [`scripts/doc_budgets.manifest.json`](../../../scripts/doc_budgets.manifest.json) + `verify_doc_budgets.py` enforce the ceilings — budgets are `wc -w` whole-file, a budgeted file gone missing fails the gate; on red, relocate, then condense, and raise the ceiling last with a justified manifest diff.

**Direction-free mirrors.** [`scripts/agentlib.py`](../../../scripts/agentlib.py) detects per-pair direction against git HEAD — never mtime, which clone and checkout reset: exactly one side differing from HEAD means that side is copied over the other; equal contents pass; both sides differing and disagreeing is a conflict the tooling refuses to guess through; a path absent from HEAD counts as changed on its side, which bootstraps new pairs. `check_agent_instructions.py` (gate) and `sync_agent_instructions.py` (fixer) share the module; the pairs cover the root and subtree `AGENTS.md` ↔ `CLAUDE.md` copies and the skills trees, where `.agents/skills/` and `.claude/skills/` are equal copy mirrors with no primary, detected file-by-file. Symlinks are rejected: a Windows checkout materializes them as regular files holding the target path. The prek hooks (`agent-instructions-sync`, `skills-sync`, `format` group) auto-fix and stage the stale twin on an unambiguous single-sided change; a true conflict fails naming the sides, the fix command, and the reconciliation steps.

**Skills.** `.agents/skills/` is the tool-neutral home (loaded natively by ZCode and Codex-side tooling); `.claude/skills/` is its mirror. Two skills joined `iterating` and `commit`: `writing-rfcs` (the record workflow — duplicate check, lifecycle, skeletons, validation) and `doc-standards` (placement, writing discipline, gate response). `iterating` gained the landing rule that decision-bearing outputs land as dcs-rfcs; `commit` carries the record-pair bundling and the pairing rules.

**The gate suite and its wiring.** All gates are stdlib-only Python in `scripts/`, per this repo's scripts rule, sharing helpers in [`doclib.py`](../../../scripts/doclib.py) and aggregated by [`doc_sync.py`](../../../scripts/doc_sync.py), which runs them in sequence, keeps each independently runnable, and restricts scope to given file arguments: `verify_md_links.py` (relative links and `#fragment` anchors resolve — over the whole gated corpus, agent instructions included), `verify_md_wrap.py` (one physical line per paragraph), `verify_md_current.py` (current-state prose in README and `docs/` only; PRINCIPLES and records narrate rationale by design), `verify_dcs_rfc_format.py` (both languages' skeletons, machine tokens, header/folder agreement), `verify_doc_pairs.py` (pair completeness, switchers, link locale, structural parity, CJK purity), `verify_doc_budgets.py` (a missing manifest means nothing is budgeted). Wiring follows the existing prek doctrine: the `doc-check` hook in the `lint` group runs `doc_sync` on staged Markdown (prek stashes unstaged changes during hook runs, so a wider scan would see a stale tree); CI is untouched — the lint job already runs `prek run --all-files`, which executes every hook over the full corpus; the four AI tool hook trees are untouched for the same reason: they delegate to the prek groups, so the new gates flow through automatically.

**Landed in tiered commits.** The in-flight work (PRINCIPLES.md, the `iterating` skill, the AGENTS/CLAUDE edits) committed as the baseline; the gate scripts and manifests landed with the corpus normalized — paragraphs reflowed to one physical line, `README.zh-CN.md` renamed and its pair re-synchronized, `PRINCIPLES.zh.md` written; the dcs-rfcs tree, contract pair, backfills, the AGENTS.md split with budgets, the mirror upgrade, and the `docs/` extraction landed together so every cross-link resolved at its commit; this record then moved `proposed/` → `implemented/` with its skeleton rewritten.

**Growth on signals, not speculatively.** Not ported, each with the trigger that would revive it: `.i18n.yaml` blob-hash sidecars and merge drivers (one-sided pair edits repeatedly slipping past review); an archived frozen tree with a sealed manifest (records accumulate past findability); `{class}/` subfolders inside lifecycles (class counts grow past browsing); a gate-scheduler DAG (gate count or runtime outgrows sequential execution); a `specs/` tier with an index gate (design facts outgrow the README overview); postmortems, PR/issue templates and policy automation (external contributors arrive); `grill-me`, `shipping`, and `release` skills (the workflows recur enough to codify). The reference project's full machinery is the recorded ceiling of where this road leads, not the starting point.

## Alternatives considered

**Port the deepseek-harness machinery wholesale.** It lost: this corpus is an order of magnitude smaller than markpost's, itself an order smaller than the reference; blob-hash i18n triplets, a frozen archive, a dependency-graph gate scheduler, postmortems, and issue-policy automation would each be the most complex script in this tree serving no need here. markpost's trigger-signal verdict was inherited deliberately — pieces arrive when a signal appears, never wholesale.

**Light wiring without layering — keep the single root AGENTS.md.** It lost: 1,242 words already taxed every session with every subtree's detail, and without a mechanical budget the accretion continues; the load paths support progressive disclosure, so layering localizes the context tax where tools support it. Raised at review and declined in favor of the full split.

**Freeze PRINCIPLES.md into the root's Conventions section — markpost's model.** It lost: markpost froze a predecessor whose rules were migrating; here PRINCIPLES.md is freshly written, is the live home the `iterating` skill operates from, and no drift problem motivates a migration. Keeping it live and pairing it bilingual is the smaller, grounded change.

**Symlink mirrors — the reference project's mechanism.** It lost: git stores a symlink as a mode-120000 blob, and a Windows checkout without `core.symlinks` plus privilege materializes `CLAUDE.md` as a regular file containing nine bytes; nothing constrains contributors to Unix-like checkouts. Copy mirrors with HEAD-based direction detection work everywhere.

**A separate CI docs workflow — markpost needed one.** It lost: markpost's lint CI path-ignores `*.md`, so docs needed their own workflow; this project's CI runs `prek run --all-files` over everything, and a second workflow would duplicate that job for no path-ignore reason.

**A `specs/` tier now.** It lost: the design facts fit the README overview and the code today; a tier plus index gate is surface to maintain and pairs to translate before any signal demands it.

**Keep the `README.zh-CN.md` naming.** It lost: `.zh.md` is the convention the new corpus was born with; two spellings for one idea is its own drift, and the pair gate would carry two regexes forever. Renaming was one `git mv`.

**Split this introduction into five records, one per subsystem.** It lost: markpost's granular records reflect an adoption that unfolded over weeks; this introduction is one decision-event, reviewed and landed as a whole, and the subsystems share one migration. Granular records start with the next trigger.

## Consequences

The harness shipped green end to end, verified as specified: all six documentation gates pass over the full corpus (29 files, 10 bilingual pairs, 8 DCS-RFC files following the format, 4 budgeted instruction files within their ceilings — the root at exactly 800 words); `prek run --all-files` passes including the new `doc-check`, `agent-instructions-sync`, and `skills-sync` hooks with `.github/workflows/` byte-unchanged; the mirror matrix was exercised by drill — a single-sided edit of any pair heals and stages the twin, identical edits on both sides pass, disagreeing edits fail naming the sides and the reconciliation steps, and a new skills file bootstraps its twin; the fast pytest suite (284 passed) and `cargo test` are green with product code untouched, and the new scripts pass ruff under this repo's configuration. The costs accepted: structural parity proves shape, not substance — a sloppy twin passes green, so review carries semantics; every future documentation change carries the bilingual duty (proportionate at this corpus size, with signal-gated upgrades deferred and named); word ceilings invite raise-churn, absorbed by headroom and the justify-in-the-manifest-diff path; the staged-only pre-commit scope means full-corpus truth lives in CI and the AI Stop hook, not in every commit; direction detection reads HEAD, so merge and rebase states that leave a pair disagreeing surface as guided conflicts, never silent copies; and every non-trivial change now carries the DCS-RFC duty the tree itself enforces.
