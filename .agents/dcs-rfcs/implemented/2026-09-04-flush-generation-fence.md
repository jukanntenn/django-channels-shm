# DCS-RFC: Per-ring flush generation fence

Status: implemented

English | [中文](2026-09-04-flush-generation-fence.zh.md)

## Problem

`flush()` resets ring counters, slot state, and the slab pool under the global flock, but the send/receive hot path never takes that flock. A `send` or pump `drain` running concurrently with a flush interleaves with the reset stores, and the interleavings are not merely "message lost": a producer that claimed a ticket before the reset publishes a stale `seq` afterwards (wedging a slot until compaction), and — worst — a producer's late `overflow_off` store can resurrect a pointer into a pool that `slab.reset` already wiped, handing a consumer recycled-or-garbage bytes (content corruption), while a consumer's late `slab.free` can push a stale page into the fresh free list for double allocation. The docstring's "must be called in a quiescent state" is caller discipline that nothing can enforce across processes, and the spec's own flush semantics make tests and admin tooling call it routinely.

## Decision

Every ring carries a **flush generation counter**, and both hot paths validate it around their critical sections:

- **Layout v2** (`layout.rs`): `RING_GENERATION` (u64, release-ordered) sits at ring-header offset 40; `RING_HEADER_SIZE` is 48. `VERSION` is 2, and `check_magic` folds the version in, so a region written by an older layout fails the check and takes the first-process rebuild path (re-initialize) instead of being misread with the new slot stride.
- **reset** (flush path, flock held) bumps the generation with release ordering **before** touching counters, slots, or the pool.
- **enqueue** loads `g0` before the claim; after the payload is written it re-loads. Changed → it retracts the unpublished round by writing NOTHING except dropping its own owner record (CAS `self → 0`): the reset state is already the correct final state for a round that never published, and any seq/overflow store here could clobber a FRESH round that re-claimed the same slot under the same ticket number after the flush (cross-generation ticket aliasing — first-round tickets are claimable again post-reset). Unchanged → it publishes `seq = pos + 1`, clears owner, and re-loads once more; changed → a single CAS retracts the published round to the tombstone value `pos + cap` (loss-only; see the aliasing windows in Consequences), keeping a consumer that already claimed safe on the intact payload and its overflow free exactly-once.
- **dequeue** loads the generation beside each `dequeue_pos` read; after a successful claim, a changed generation means the pool was wiped — it recycles the claimed slot to the tombstone **without** freeing its overflow page into the fresh free list and returns `None` (the caller retries from the fresh `dequeue_pos`).
- **dequeue** likewise writes only the tombstone CAS and its owner clear on a raced claim; the claimed round's overflow page is never freed into the fresh pool (the generation change proves the pool was reset — freeing there is the double-allocation hazard). What remains irreducible in this encoding is cross-generation ticket aliasing: post-reset, fresh traffic legitimately re-claims the same ticket numbers, so an old-generation producer cannot distinguish its round from a fresh one by slot value alone. The design therefore minimizes what a raced operation writes (owner-CAS only for unpublished rounds; one guarded CAS for published ones) and documents the two surviving windows in Consequences.

## Alternatives considered

**Wait-for-quiescence flush (scan slot owners under flock, retry until clean).** It lost: the claim→owner-set window is 2–3 instructions and invisible to the scan, so a racer's late `seq` publish still wedges a slot and its late `overflow_off` store still resurrects a freed page.

**Logical flush (advance counters and slot seqs to their next tickets; never rewind).** It lost: a racer's late publish regresses a repaired slot back behind the frontier (wedge), and the overflow-page problem is unchanged — without a generation the racer cannot know its page was released.

**Producer-side flock gating on a shared flush-pending flag.** It lost: the flag is itself new shared state (same layout cost), and it serializes the two operations with two flocks instead of one counter check.

**Document-only (keep the quiescence discipline as the contract).** It lost as the end state: the corruption is reachable by any correct-looking caller that flushes a layer with live senders, and "discipline" is not a memory-ordering argument. It was the interim mitigation until this landed.

## Consequences

The unbounded flush-critical-section race is closed: raced operations retract instead of publishing into, or freeing pages of, the wiped pool; the instructions-wide window between the last generation check and the `seq` store / `slab.free` remains, with the pump's P-01 malformed-message tolerance as the last-resort net. Two cross-generation aliasing windows also remain, each requiring a producer parked across a flush by SIGSTOP-grade pathology: (1) a producer parked between its publish and the post-publish check can CAS-retract a fresh round that reused the same ticket number — an accepted send is LOST, never corrupted (skipping the retract would instead let the stale pre-flush message surface with a pointer into the wiped pool — content corruption, strictly worse); (2) a parked producer's own late payload stores can tear a re-claimed round's bytes — torn bytes fail msgpack unpacking at the pump and are dropped (P-01), not delivered as application messages. A dedicated aliasing stress test (a parked 2 MiB producer, a reset, then a fresh round on the same slot) pins the retract invariant — a published fresh round is never tombstoned — and was verified to fail against the pre-fix retract, which tombstoned the fresh round deterministically. Rust (producer + reset-storm threads) and Python (asyncio send/flush interleaving) stress tests pin the broader contract — no hang, no crash, survivors parse, the layer and ring are fully functional after the storm — and a version-gate test pins the v1-region rebuild. Mixed old/new processes on one region corrupt each other until the first new process rebuilds it; acceptable under the single-machine, single-deploy distribution of the extension. Measured cost (criterion, this machine): uncontended enqueue 36.8 → 40.6 ns, of which CAS-claim admission is +0.6 ns (36.8 → 37.4) and the fence's load + branch +3.2 ns (37.4 → 40.6); dequeue 78.6 → 76.8 ns. Both are far inside the 100 ns anchor gate, which passes. Contended numbers on this machine carry high run-to-run variance (the same code measured +58% and +2.5% on the 8-thread enqueue across runs) — single contended readings are noise; the anchored uncontended gates are the reliable signal. All existing flush tests pass unchanged.
